功能简介｜飞书多维表格扩展视图插件 ——「卡片视图」

项内容
产品名称卡片视图（Card View）
产品形态飞书多维表格插件 · 数据表视图类型（出现在「新建视图」的视图类型列表中）
发布形态飞书企业自建应用（非应用商店上架）
当前版本v1.5.0
文档日期2026-09-23
配套文档05-功能简介.md（本文）、06-使用说明书.md（操作手册）

1. 一句话定位

把「横向拖表格找字段」变成「一眼看清关键信息的卡片墙」 —— 不改变字段、不复制数据，为同一张多维表格定制出最贴合业务阅读习惯的卡片视图。

它不替换你的表，也不搬走你的数据：只是给同一份数据换一副「以业务语言阅读」的面孔。

2. 它解决什么问题

常见困扰卡片视图的做法用户感受到的变化
字段多，要横向拖动才能看到关键列每条记录收敛为一张卡片，关键字段按重要性排进固定槽位一屏看完一批记录，不再横向滚动
同一张表不同场景想要的版式不同（客户视角 / 盘点视角…）同一张表可建多个卡片视图，各自独立配置不必复制表格、不必删字段
详情要看的东西和列表不一样详情沿用同一套自定义排版，支持扩展为全字段卡片与详情视觉一致，学习成本为零
异常记录（逾期、超期）靠肉眼扫条件高亮：按字段值给整卡边框或字段着色异常一眼可见
排版要给非技术同事用，但改版式要开发可视化拖拽排版 + 模板套用 + 撤销业务人员自己就能改
已有 Word 模板（合同、标签、工单）想直接套用导入 .docx 模板 + 占位符读表格字段沿用既有模板，不必重画

3.1 阅读侧（所有人可用）

密度三档紧凑 / 标准 / 宽松 —— 联动卡片宽度、间距、行数与属性区最多行数

记录详情点击卡片（或聚焦后按 Enter / 空格）从右侧滑出详情抽屉；单张连续长页，可缩放、全屏、拖宽

大表流畅浏览每批 200 条增量加载，滚动到底部自动续载；骨架屏过渡

团队共享配置存于飞书文档级存储（按视图隔离），同一文档同一视图的成员共用一套版式

4. 关键主张与保障

  • 数据不搬家：数据始终留在原多维表格，插件只改变「呈现层」，不产生数据副本与同步风险。
  • 只读不污染：插件不写入表格数据，不改写视图的原生筛选 / 排序；唯一会写的是插件自有的排版配置。
  • 筛选不外泄：筛选在插件内客户端求值，绝不下推服务端，因此不会影响他人看到的原生视图。
  • 配置有兜底：配置损坏时自动回退默认排版、保留原始数据备份，并明确提示「未改动你的表格数据」。
  • 权限自适配：无编辑权限的用户只读浏览（配置入口自动隐藏/禁用）；遇到更高版本插件写入的配置时进入只读模式，不覆盖较新数据。
  • 零新增依赖：产物自包含、无自建后端、无外部 CDN。

5. 典型场景

  1. 客户档案卡：标题=客户名称，副标题=所属行业/负责人，属性=合同金额/最近跟进时间，底部=状态标签。销售开会前一屏 30 张卡，3 秒定位重点客户。
  2. 项目进度墙：属性区放负责人/截止日期/进度，配置条件高亮「逾期记录卡边变红」，晨会直接投屏。
  3. 工单/合同套打信息：用既有 Word 模板导入，占位符绑定字段，点开卡片即见一份按模板生成的完整单据信息（本期为信息呈现，不含打印导出）。

6. 适用范围与边界

维度说明
适用端桌面端飞书客户端与网页版（移动端完整编辑不在本期范围）

1. 快速上手（5 步）

  1. 打开视图：在多维表格「新建视图」中选择卡片视图；已创建的可直接从视图列表切换。
  2. 首次打开：插件会按默认模板生成一份配置，并提示「首次打开已按默认模板生成配置，可直接使用或按需调整。」（如需重配可点横幅上的「立即配置」）。
  3. 配置排版（需表格编辑权限）：点工具栏 ⚙ 配置 打开「卡片排版编辑器」——左侧拖字段、中间实时预览、右侧调属性；改完点 保存。
  4. 筛选用：点工具栏 筛选 → + 添加条件 → 选字段、选算子、填值（即时生效）→ 点 完成 收起面板。
  5. 看详情：点击任意卡片，右侧滑出详情；按 Esc 或点 ✕ 关闭。
没有编辑权限时，⚙ 配置 按钮为禁用态（提示「仅查看权限，无配置入口」），浏览、搜索、筛选、看详情一切照常可用。

3. 浏览记录

3.1 卡片结构

一张卡片按四个槽位自上而下排列：标题 / 副标题 / 属性 / 底部。

  • 标题、副标题：多字段时用 · 连接；标题单行省略。
  • 属性：每行「字段名（左）+ 值（右）」；行数受密度与模板上限约束，超出的有值行在末尾显示 +n。
  • 底部：标签样式。
  • 无值字段默认隐藏（不会显示空白行）；整个槽位都没有内容时该槽位自动收合。
  • 字段被删除时，卡片上自动隐藏该行。

3.2 密度三档

档位卡片最小宽度间距内边距属性区最多行数

标准280px16px16px3
宽松320px20px20px5

3.3 计数文案

情况文案

收窄且已加载全部共 12,480 条（已筛选 37 条）

平台未返回总数（收窄且未加载全部）已在已加载的 200 条中筛选，命中 37 条

为什么会有「已加载的 N 条」：为流畅浏览，插件每批加载 200 条，滚动到底部附近自动续载（加载时网格底部出现骨架行）。 筛选或搜索一生效，插件会自动把全部记录加载完再筛选（见 §5.1），加载期间状态行会如实标注范围与进度。

4. 搜索

  • 位置：工具栏中部搜索框；输入即过滤（无需回车）。
  • 匹配范围：只匹配卡片排版中已引用字段的显示文本（即你看到的卡片文字），大小写不敏感、子串匹配。
  • 不匹配：未放进卡片的字段；字段的原始 ID / 技术值。
  • 叠加关系：先筛选、后搜索，两者同时生效（AND）。
  • 作用范围：仅已加载记录；不与服务端交互。
  • 清空方式：搜索框内 ✕、⋯ 菜单的「清空搜索」、无结果空态的「清空搜索」按钮。

5. 字段筛选

5.1 面板操作

  1. 点工具栏 筛选 打开面板（面板头提示：筛选对已加载记录即时生效）。
  2. 点 + 添加条件 新增一行；每行三步：选字段 → 选算子 → 填值。
  3. 条件数 ≥ 2 时，面板出现 与 / 或 切换（默认 与，单层组合，不支持嵌套）。
  4. 筛选在全部数据中生效：条件一旦生效，插件会自动把全部记录加载完毕再计算命中（记录少时无感完成；记录多时状态行显示进度 已加载 L / 共 T 并出现取消加载按钮）。加载期间你调整条件也没关系 —— 加载完成后会按最新条件重新计算，不会用旧条件给你结果。
  5. 点 完成 只是收起面板 —— 筛选在填写时已经生效（这点与「应用」按钮的直觉不同，故按钮名刻意叫「完成」）。
  6. 清空 一键清除全部条件（无条件时按钮禁用）；清空筛选不会触发全量加载。

5.2 选字段

  • 字段下拉支持模糊查询：输入关键词即过滤（去首尾空格、大小写不敏感、子串匹配字段名或类型提示）。下拉框右侧有 🔍 图标，展开后顶部提示「输入关键字筛选」。
  • 无匹配时显示 无匹配字段。
  • 下拉只列出可筛选的字段；若当前条件用的字段不支持筛选或已被删除，该字段仍会置顶显示并标注 （不支持筛选） / （字段已删除）。

5.5 无效条件如何提示（重要）

条件行若不会生效，会整行标红并给出具体原因（按优先级）：

原因文案
算子未知该条件不会生效：未知算子「xxx」
类型 × 算子不匹配（含字段已删除）该条件不会生效：所选算子不适用于此字段类型
值未填写该条件不会生效：尚未填写筛选值

同时面板顶部出现汇总：⚠ 有 N 个条件未生效，已按其余条件筛选；状态行追加以括号后缀 （其中 N 个条件未生效）。

5.6 「空值条件不会隐藏数据」（设计保证）

新增条件行不会预填值。在你填写之前：

  • 该条件被标红提示 尚未填写筛选值；
  • 卡片数量不变（不会因为一条空条件把记录全部筛掉）；
  • 若所有条件都未生效，则视为「不筛选」，显示全部记录，并提示「N 个条件未生效」。
  • 为空 / 不为空 两个算子永远有效，不需要填值。
这条规则的意义：宁可筛选暂不生效，也绝不让记录被静默隐藏。

5.7 与原生表格筛选的关系

本插件的筛选完全在插件内计算，不会写回、也不会改变表格视图的原生筛选设置；两者互不影响。排序则直接沿用原生视图的排序结果。

6.1 关联字段：以只读表格展示

详情里遇到关联 / 双向关联类型的字段时，不再只显示一行拼接文本，而是把关联到的记录按表格呈现（与多维表格原生详情的观感一致）：

项行为
列默认取「对方表的主字段 + 前 3 个可用字段」（自动跳过不支持的类型）
行关联到几条就显示几行；单字段最多 20 行，超出时在末尾显示 +N（不静默丢行）
只读没有任何操作入口：不能排序、不能编辑、不能「+ 添加记录」、不能改字段配置
隐私关联记录的内部 ID 只用于内部定位，不会出现在页面上
取不到时某一行读取失败 → 该行保留占位（不影响其它行）；整体取不到 → 退回原来的文本显示，不报错、不白屏
说明：这些记录是逐条按需读取的（平台没有「按 ID 批量取」的接口），因此关联行数多时首次打开会稍慢；上限 20 行既是性能保护，也是防「一次拉太多」。
⚠️ 列的可配置入口在下一版提供（当前固定为默认列规则）。

9. 导入 .docx 模板

9.1 上传与规则

  1. 「模板来源」选 导入 docx → 点 选择 .docx 模板。
  2. 规则：
  • 仅接受 .docx（其它类型提示：仅支持 .docx 模板文件（当前文件：xxx））。
  • 单个模板 ≤ 1MB（超限提示形如：模板 33.0KB（33792 字节），超出上限 1024.0KB（1048576 字节），请压缩模板后重试）。

  1. 已上传后按钮变为 重新选择 .docx；当前模板以 文件名（体积） 形式展示（如 合同模板.docx（28.4KB））。

9.2 占位符语法

写法含义
{字段名}插入该字段的值（按数据表格式显示）
{#关联字段名}…{/关联字段名}循环段：把该「关联字段」关联到的记录逐条展开（明细行/子表用法）

规则与边界：

  • 字段名前后空格会被忽略；大小写敏感；精确匹配，不做模糊/近似匹配 —— 写错一个字就会进「未匹配」而不是猜。
  • 无法配对的 { 或 }、空标签 {} / { }、空名标签 {#} / {/} 一律按普通文本处理，不会吞掉你文档里的字符。
  • 不支持 ^（反向段）、-（局部段）、=（换分隔符）等高级前缀写法；这类内容会被当作「名字以此开头的占位符」并在体检中报「未匹配」。
  • 字段重名：若表中有两个同名字段，该占位符不会取第一个，而是留空并在体检中报「重名冲突」。

9.3 体检结果怎么看

区域文案含义与处理
匹配成功匹配字段 N 个正常（绿色）
未匹配模板里写了、但没有对应字段的占位符（导出后是空白，请核对字段名） + 占位符原文逐条核对字段名拼写/空格/大小写
重名冲突字段重名导致无法确定用哪个字段（已留空，不会猜） / 源字段重名冲突（无法确定用哪个字段） + 候选字段 id请先重命名表格字段，使名称唯一
循环未闭合循环未闭合（写了开始标签，但没有对应的结束标签） + {#x} 缺少 {/x}补上结束标签
多余结束标签多余的循环结束标签（没有对应的开始标签） + {/x} 缺少 {#x}删掉或用错位处修正
未引用字段模板未引用的字段：A、B提示性信息（弱化色），不影响导出
体检的价值：提前告诉你哪些占位符会渲染成空白 —— 否则文档看起来「有内容」，但那些位置悄悄是空的。

11. 常见问题（FAQ）

Q1：筛选是在全部数据里筛吗？为什么有时要等一会？ 是，在全部记录中筛选。条件一生效，插件会自动把全部记录加载完（每批 200 条）再计算命中；记录多时需要几秒到几十秒，期间状态行显示进度并可取消加载。加载完成前状态行会如实标注「已加载的 L 条」，不会谎称已覆盖全部。

Q1b：计数为什么不显示「共 N 条」了？ 当平台没有返回记录总数时，插件会改用「已加载条数」作分母（如 已在已加载的 200 条中筛选，命中 5 条），以避免出现「共 0 条却命中 5 条」这种自相矛盾的提示。总数正常返回时会恢复显示 共 N 条。

Q2：我点了筛选面板里的「完成」，为什么筛选没有应用？ 「完成」只是收起面板 —— 筛选在你填写时就已即时生效。所以按钮名才不叫「应用」。

Q3：我新加了一条筛选条件还没填值，卡片怎么没变化？ 这是故意设计：未填值的条件被判为「未生效」并跳过，记录保持可见（你会看到行内红字「尚未填写筛选值」）。填上值后才参与筛选。

Q4：条件行标红了，什么意思？ 说明该条件当前不会生效，红字会告诉你具体原因：值没填 / 算子不适用此字段类型 / 算子未知。此时其余条件仍照常生效，状态行会注明「其中 N 个条件未生效」。

Q5：搜索为什么搜不到某个字段的内容？ 搜索只匹配已放入卡片的字段显示文本。若该字段没被拖进任何槽位，请先把它加进卡片。

Q6：详情里的字体/纸张和我配置的不一样？ 如果你用的是导入的 docx 模板，详情会以模板自带的页面尺寸与页边距渲染（保真优先）；只有「可视化排版」来源才应用 §8.4 的页面设置。

Q7：模板里的字段没显示出来（位置是空白）？ 去看「模板体检」的「未匹配」列表 —— 大概率是字段名拼写/空格/大小写对不上；也可能是表格里有重名字段（会明确报重名冲突）。占位符按字段名精确匹配，不会猜。

Q8：导入大模板很慢或失败怎么办？ 先点 检测存储容量 看当前平台可写入到多大（常见档位边界是 64KB）。若失败提示里带 （可能是平台单键存储上限导致，请压缩模板后重试），请压缩模板（例如去掉大图、精简样式）后重试。

Q9：详情里的关联字段变成表格了，为什么只能看到 20 行、列也只有几列？ 这是按需求做的「关联字段表格化」：默认列 = 对方表主字段 + 前 3 个可用字段，单字段最多 20 行（超出显示 +N）。关联记录是逐条读取的（平台无批量接口），限行是为避免一次拉太多导致卡顿；列配置入口在下一版提供。

Q10：为什么别人看不到我改的排版？ 看页面顶部是否有「配置仅本地保存」提示 —— 说明当前环境的飞书存储不可用，配置降级保存在本机。请在飞书客户端中打开该文档重试。

Q11：卡片上的字段比我配的少 / 多出一个「+2」？ 属性区受密度档位（紧凑 2 / 标准 3 / 宽松 5 行）与模板上限共同约束，超出的有值行会被折叠为 +n 提示。调大密度或改用属性更多的模板即可。

Q12：这个插件会不会改我的表格数据或原生筛选？ 不会。插件只读表格数据，不写回数据，也不改写视图的原生筛选/排序；唯一会写入的是插件自己的排版配置。

12. 已知限制（请留意）

  1. 关联记录的列暂不可配：详情里关联字段的表格固定用「对方表主字段 + 前 3 个可用字段」作为列；选列的配置入口在下一版提供。
  2. 关联表格单字段最多 20 行：超出显示 +N；关联记录是逐条按需读取（平台无按 ID 批量接口），行数多时首次打开会稍慢。
  3. 打印导出未包含在本期：详情为屏幕阅读形态，不含打印/导出 PDF 能力（后续规划）。
  4. xlsx 模板未支持：本期模板仅 .docx（后续规划）。
  5. 页眉 / 页码 / 页脚不再可配：详情已改为单张连续长页；历史配置中的相关字段会保留但不再影响显示。
  6. 详情抽屉不能在记录间切换：没有「上一条/下一条」，需关闭后另点卡片。
  7. 全量加载需要时间：记录多时（万行级约 60 批）首次筛选需要数秒到数十秒，期间可取消；取消或加载失败时状态行会明确标注「未加载全部」，不会伪装成已覆盖全部。
  8. 单一 AND/OR 层级：筛选条件支持一层「与/或」，不支持条件嵌套分组。
  9. 悬浮预览内容有限：仅标题 + 属性区前 4 行。
  10. 排序不可在插件内调整：沿用原生视图排序（插件内只提供说明）。
  11. 配置损坏横幅的「重试读取」按钮尚未修复：当前它只重新加载记录、不会重新读取配置，因此点了横幅不会消失（已在修复计划中）；同时该横幅目前不显示具体损坏原因，插件的控制台会输出 [cbv:config.load] 日志（含原因与原始配置片段），排查时请提供这行日志。
